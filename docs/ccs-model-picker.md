# `/ccs` 供应商与模型卡片

> **上线前提：完整 Codex 模型列表需要 CC Switch 控制接口包含模型目录修复。** 仅更新 cc-connect 或刷新卡片，不能补齐旧接口遗漏的模型。卡片部署记录见 [飞书卡片更新](../../ccs-picker-feishu-deploy/README.md)，本次模型目录修复状态见 [修复说明](../../ccs-model-catalog-fix/README.md)。不得为此重跑既有 Stage / Activate / Rollback / Queue 脚本，也不要覆盖 `ccs-repair` 基线。
>
> **验证状态：卡片专项、全部 CUJ 与构建已通过，但 Windows 全量测试和全量 `go vet` 未通过。** 这是待上线测试版，不代表仓库所有测试已通过。
>
> **切换范围：供应商属于 CC Switch 的共享代理；模型沿用当前项目或绑定 workspace 的 `/model` 设置。** 同一代理的其他使用者也可能受供应商切换影响。确认前请查看卡片中的当前值与目标值。

提供类似 Hermes 模型选择器的原生下拉交互：**选择供应商 → 选择模型 → 确认应用**。入口为 `/ccs`，本次不替换原来的 `/model` 命令。

## 开始选择

在机器人会话中发送：

```text
/ccs
```

1. 在供应商下拉中选择目标。也可以选择当前供应商，只更换项目模型。
2. 在下一屏选择该供应商的模型。
3. 核对供应商、模型和共享范围，点击“确认应用”。
4. 结果卡片显示应用结果，并允许继续选择。

飞书优先更新点击的原卡片，而不是持续发送新卡片。原位更新失败时会补发结果卡片，**只重试消息投递，不重复执行切换**。

以下操作不切换供应商或模型：打开菜单、选择下拉项、翻页、返回、刷新、取消。只有最后的确认按钮会应用选择。旧的显式 `/ccs switch ...` 命令仍保留原有直接切换行为，不经过这个确认流程。

可用入口：

| 命令 | 用途 |
| --- | --- |
| `/ccs` | 打开选择器 |
| `/cc-switch` | 同一入口的别名 |
| `/ccs current` | 读取当前状态并显示菜单 |
| `/ccs list` | 读取供应商目录并显示菜单 |
| `/model` | 保留原有项目模型菜单，不改成 CC Switch 入口 |

## 模型列表的来源与刷新

下拉数据来自 **CC Switch 控制接口公开的已配置模型**，不是在线查询供应商的完整模型列表，也不会补入猜测的模型名称。

- Claude 目录可包含默认模型及已配置的模型档位。
- Codex 目录包含默认模型，以及该供应商在 CC Switch 中保存的全部 `modelCatalog.models[].model`。默认模型排在前面，其余按保存顺序展示；去除首尾空白和重复 ID，不按显示名称合并不同模型。
- 每页最多 50 个模型，更多模型通过“下一页”查看，不会只保留前 50 个。新增模型并在 CC Switch 保存后，重新发送 `/ccs` 或刷新菜单即可读取新目录。
- 若供应商未提供任何模型，显示“保持模型，只切换供应商”的确认流程。
- 选择的是项目 `/model` 所用的模型；**最终上游模型仍可能被 CC Switch 的代理映射改写**。
- 本实现不调用 CC Switch 尚未作为当前通用控制契约开放的模型修改接口，也不修改供应商的默认模型配置。

若保存了多个模型却仍只能看到默认模型，应先确认**运行中的 CC Switch** 已安装本次控制接口修复；只重新构建或重启 cc-connect 无法修复旧接口。模型目录只返回模型 ID，不公开认证信息、完整供应商设置或模型元数据。

## 显示卡片的条件

| 条件 | 行为 |
| --- | --- |
| 当前项目已配置 `ProviderController` | 沿用已有 CC Switch 控制接口集成，无需新增端口 |
| 平台支持 `CardSender`，agent 支持 `ModelSwitcher` | 展示供应商与模型选择器 |
| 飞书 `enable_feishu_card` 未设为 `false` | 默认启用交互卡片 |
| `ccs`、`provider` 和 `model` 命令权限允许 | 回调通过正常命令入口检查权限，不绕过角色限制 |
| 无卡片能力、无模型切换能力，或禁止 `/model` | 退回原供应商菜单或纯文本，不提供模型选择 |

本次不改写任何生产配置。若运行实例主动关闭了飞书卡片，需要在后续受控更新中单独检查该设置。

## 遇到错误时

| 提示或现象 | 原因与处理 |
| --- | --- |
| 卡片已失效 | 每屏凭据有效期 10 分钟且单次使用；重新发 `/ccs`。目录、当前供应商、项目模型或 workspace 改变时也会拒绝旧确认。 |
| 旧卡片不能继续点击 | 同一用户在同一会话新开菜单会替换自己的旧选择状态；使用最新卡片。 |
| 会话或选择操作忙碌 | 等当前会话本轮任务或当前切换结束后，重新打开菜单；不会为切换而中断任务。 |
| 代理停止、自动故障转移开启或供应商不可选 | 可以查看目录，但不能应用该选择；先在正常管理流程中处理原因。 |
| 供应商未确认 | 控制接口未明确确认目标供应商，项目模型不会继续修改；先用 `/ccs current` 核对实际状态，不要假定切换一定失败。 |
| 供应商已切换但项目模型应用失败 | 会明确报告部分成功，不盲目回滚共享供应商；核对当前值后再处理模型保存问题。 |
| 点击别人的卡片或重复确认 | 凭据绑定用户与会话，重复、跨用户、跨会话回调不能再次应用选择。 |

状态仅保存在内存中，最多保留 128 屏待处理选择；服务重启后旧卡片失效。每页最多 50 项。回调携带随机凭据与选项索引，不把供应商名称、模型名称或配置凭据放进命令参数。

供应商切换与模型保存不是跨进程原子事务。当前 Engine 会串行处理自己的 `/ccs` 写操作，并在确认前重新校验目录、模型和 workspace；其他项目、桌面操作或外部进程仍可能改变共享代理。不会尝试通过自动回滚覆盖其他使用者的选择。
